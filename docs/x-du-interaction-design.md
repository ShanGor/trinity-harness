# 小杜在 Trinity 中的互动设计

> 产品提案 · 2026-11-02 · 待评审，尚未实现

## 定位

小杜是 Trinity 的可选数字伙伴：让等待、语音交流和主动互动更有温度，同时让聊天、工作与审批仍然清晰可靠。它用动作表现界面已知的状态，不替 Agent 作决定，也不把动画当成任务成功的证据。面向长期使用，默认克制，用户想玩时再展开丰富动作。

素材来自 `/home/sam/sources/x-du-bot`：`public/models/mimo.glb` 是静态刚性部件模型，动作由 Three.js 的 `RobotController` 驱动，并非 GLB 内置骨骼动画。现有驱动包含待机、倾听、思考、说话、挥手、击掌、魔法等动作，以及表情、注视和语音强度接口。正式集成前需确认素材使用权及第三方依赖许可，并验证资源体积与设备性能。

## 体验方案

### 日常陪伴

在聊天界面边缘提供一个小型角色区域，首次展示时轻轻挥手，之后以呼吸、眨眼和轻摆待机。点击角色打开小面板：当前状态、几个互动动作、收起及设置。角色不遮挡消息、输入框、审批和来源；窄屏使用可收起的小入口，展开时占用明确的界面空间。用户关闭后持续尊重其选择，不在导航或刷新后突然出现。

它的状态由当前可见会话和本地语音播放状态驱动，并配有文字，不能只靠姿态传递信息：

| 场景 | 展示 | 规则 |
| --- | --- | --- |
| 空闲 | `idle`，文字“待命” | 低幅度循环，无声音 |
| 已开启语音且正在收音 | `listening`，“正在听” | 以真实收音状态为准；麦克风关闭即退出 |
| 正在推理 | `thinking`，“思考中” | 根据当前会话可确认的推理状态展示；不暗示具体进度 |
| 正在执行工具或工作 | `magic`，“工作中” | 工作开始时播放一次；动作结束后保持安静待机并继续显示“工作中”，不重复播放 |
| 处理中但阶段未知 | `idle`，“处理中” | 不猜测当前正在推理还是执行工具 |
| 等待审批 | 停止表演，文字“等待你的确认” | 原有审批卡片始终是唯一操作入口 |
| 播放语音回复 | `speaking`，嘴型随实际播放音量变化 | 停止、打断或播放结束立即停止嘴型；文字流本身不假装有声音 |
| 回复结束 | 回到待机 | 不自动庆祝：完成不等于目标已达成 |
| 出错或取消 | 温和的 `confused` 或待机，配实际状态文字 | 不夸张表达、不掩盖错误详情 |
| 连接不明 | 待机，“状态暂不可用” | 不推测成功、失败或正在工作 |

状态是界面提示，消息、执行历史和审批仍是事实来源。多个会话并行时，角色只展示当前可见会话；切换会话立即重算，旧会话的迟到事件不能覆盖新状态。重连先依据恢复后的状态显示，无法确认时显示状态不可用，不重播历史庆祝动作。

### 主动玩一会儿

面板提供“打个招呼”“击掌”“变个魔术”三个明确按钮，分别播放 `greet`、`highFive`、`magic`。点击角色也可触发一次轻微回应；触摸区域可在后续验证后加入，避免小屏误触。动作可中断、不排长队，连续点击限频；播放完回到真实状态。特效和声音默认关闭，只有用户主动开启时使用；手动播放魔法不表示工具正在执行；状态文字仍以实际会话状态为准。

### 语音陪伴

通话时角色倾听和说话，嘴型优先取本地 TTS 播放的音量包络；拿不到音量时使用温和的通用口型，不上传音频或记录音量。角色不自行打开麦克风、不改变语音回合、静音、打断或审批规则。挂断后恢复文本界面状态；未播放语音的流式文本不触发说话口型。

## 互动优先级与边界

审批、错误和连接异常的文字提示优先于表演；真实语音播放优先于普通待机和手动动作。推理与工具执行交替时，以最新可确认的阶段切换 `thinking` 和一次性 `magic`；阶段未知时显示通用处理中。新状态到来时取消旧动作及队列，结束后按最新状态恢复，不重放积压动画。减少动态效果设置开启时使用静态姿态和状态文字；提供键盘可操作的按钮及屏幕阅读器标签，状态播报去重，避免逐帧通知。角色不制造额外通知、不模拟人类情感承诺、不读取对话内容推断用户情绪。

## 实现方向

作为 Web 客户端的可选呈现层，订阅现有 ACP 客户端投影及语音播放生命周期，通过小型状态映射驱动角色；不新建每组件 EventSource，不改变 Agent Loop、会话事件或模型上下文。状态映射与渲染分离，动画不可用不影响聊天、语音和审批。角色设置初期可使用浏览器本地持久化；跨设备同步需另行设计账号设置及迁移。

模型及驱动应按现有许可审查后以明确版本纳入前端构建，保留节点名称；按需加载，卸载时停止渲染、取消监听并释放控制器、模型和 GPU 资源。后台或不可见时暂停渲染；WebGL 失败、加载失败或低性能设备降级为静态入口与文字状态。现有素材文档记载模型约 79 个 mesh、13.75 万三角面，这是素材侧数字，不能视为 Trinity 内的性能实测。先在目标桌面和手机设备测量加载、帧率、内存和电池影响，再决定默认开启范围。

## 分期与验收

1. **基础陪伴**：可开关角色、待机、会话状态文字、审批/错误反馈、降级与无障碍。验证会话切换、重连、刷新、审批和取消时状态准确；角色不能遮挡操作，失败时聊天正常。
2. **语音联动**：接入实际收音和 TTS 播放状态，验证静音、打断、挂断、切换会话和播放失败均及时停止相应动作，不改变既有语音流程。
3. **趣味互动**：加入三个主动动作和可选特效，验证重复点击、动作中断、减少动态效果以及键盘操作；通过用户反馈衡量是否有趣、是否分心。

上线前在目标设备和真实浏览器检查布局、性能和资源释放，并用可控 ACP/语音状态测试状态优先级及迟到事件。产品评审需要决定角色默认开启范围、入口位置和是否采用“小杜”作为产品名称；这些是提案，不代表现有能力已经交付。
