## 1. Project Overview

An enterprise-grade, multi-user, browser ↔ server general-purpose AI Agent platform. Software engineering is a first-class task domain, alongside research and other specialist work.

## 3. Architectural Rules (violations = rejection)

1. **`packages/contracts` is the core of the entire design**: all inter-module communication goes exclusively through TypeScript interfaces (ports) defined there.
   - ❌ Modules importing each other's implementation packages (e.g., `modules/a` importing a concrete class from `modules/b`).
   - ✅ Depend on interfaces, inject via constructors; composition (assembly) exists only at each `apps/*` entry point.
2. **No `new XxxService()` inside business modules** — the object graph is assembled at the composition root.
3. **Event sourcing**: session state = a projection of the event log. Everything visible to the model must be replayable from the log. No shortcuts like "directly updating the messages table".
4. **Fail-Closed**: for security concerns (permissions, approvals, secrets), a missing component or timeout always results in denial — never degrade gracefully to "allowed".
5. **Stateless services**: `server` / `agent-worker` hold no local mutable state; state lives only in PostgreSQL / Redis / object storage.
6. **No Plugin concept**: do not introduce Cordis or any "plugin framework". Extension points = contracts interfaces + DI + MCP.
7. **PostgreSQL is the single source of truth**; Redis Stream / SSE are distribution layers that may be truncated and may lose data.

## 4. Coding Standards

### 4.1 TypeScript

- Enable `strict` in full; `any` is allowed only at external JSON boundaries (and must be immediately narrowed with Zod).
- **Define all cross-process/cross-module data structures with Zod schemas** and infer TS types from them (`z.infer`); do not hand-write duplicate interfaces. Shared frontend/backend schemas go in `packages/shared`.
- Use discriminated unions for event types, with `z.discriminatedUnion`.
- Public APIs must have explicit return type annotations; private functions may omit them.
- Error handling: use `Result` types or custom `Error`s with a `code` for recoverable errors; no empty `catch {}` blocks; no exceptions for normal flow control.

### 4.2 Async & Resources

- All concurrent code must support `AbortSignal` cancellation (LLM streams, tool execution, SSE connections).
- Async resources (streams, LSP subprocesses, Redis connections) must have a deterministic shutdown path — provide `dispose()` / `[Symbol.asyncDispose]`.
- No bare `setTimeout` polling; use events or `AbortSignal.timeout`.

### 4.3 SQL / Data Layer

- The `session_events` table is **append-only**: only `INSERT` and `SELECT` are allowed; no `UPDATE`/`DELETE` (enforced by a PG trigger in addition to migrations/retention jobs).
- All schema changes go through Drizzle Kit migration files (`packages/db/src/schema.ts` → `pnpm db:generate` → review SQL in `packages/db/migrations/` → `pnpm db:migrate`); never alter tables at runtime in code, never use `drizzle-kit push` outside local experimentation.
- Multi-row writes use transactions; `session_events` appends must guarantee monotonic `(session_id, seq)` via PG transactions + row locks (current impl: `pg_advisory_xact_lock` per session in `packages/db`).

### 4.4 Frontend

- Chat / Work are immutable server session kinds over ACP. Offer the choice only in New before durable creation; show workspace and permissions in Work setup. Main chat has one durable tenant/user identity, ordered queued prompts, topic/date history and scoped memory. Chat has its own automatic session workspace and the configured tools, including workspace CRUD, browser, knowledge retrieval and execution; Task/Work selects a workspace. Do not remove capabilities solely because a session is Chat; effective permissions, authorization and deployment availability govern tools. Preserve composer nodes, per-session drafts and streams across navigation; keep audit in the account menu. Scheduled states that recurring execution is unavailable until a durable scheduler exists. See design §11.5/§21 and `docs/refactor-as-personal-assistant.md`.

- Usage accounting is projected from append-only `model/usage` events with request/prompt IDs and per-request model/price snapshots. Keep cache reads/writes separate from uncached input, count reasoning only within output, preserve unavailable buckets/prices, and never reprice historical requests when a model/config changes. Both server and agent-worker load the single price catalog from the fixed `config/models.yaml` path; do not add environment-variable or Helm-value pricing sources. See `docs/usage-accounting.md` and design §17.

- Components consume ACP message types; antd components map 1:1 to ACP messages (see `docs/design.md` §11.5); do not invent a second private protocol.
- SSE client logic lives in `packages/client-acp` (reconnection, backoff, Last-Event-ID, gap detection); UI components must not each hand-roll their own EventSource.
- Redis session publication batches tolerate replayed/late IDs while propagating other failures. Server Redis readers repair internal sequence gaps from PostgreSQL before delivering newer events; preserve PG authority and bounded gap pages. Runtime latency metrics separate model dispatch preparation/streaming and guest RPC phases; never add secrets or identity/path labels to metrics. See design §21.5.
- Model-facing tool schemas exclude explicitly denied tools while retaining approval-gated tools; execution still enforces policy on every call. Guest read failures use bounded typed operation errors only after binding/authorization validation; never reinterpret unknown transport or mutation failures as harmless file errors. Roll out control-plane readers before guest writers. See design §21.5.
- Terminal EventSource failures must reconnect from each subscription's delivered cursor with cancellable backoff. The Vite API proxy must close downstream responses when the upstream disconnects incompletely, so SSE does not remain silently open after a backend restart.
- Live text/thought chunks must bypass log-sequence deduplication: browser EventSource inherits the last committed ID on frames without `id:`. Keep live rendering immediate, including resumed sessions and later assistant steps. Composer autosizing uses `@chenglou/pretext` with cached DOM metrics and prepared text on resize; preserve the textarea node, focus and draft.

## 5. Security Baseline

- Secrets (model API keys, etc.) are stored server-side only (K8s Secret + envelope encryption) — **never sent to the frontend, never written to logs or event payloads**.
- All user input (prompts, file names, tool arguments) is validated with size limits at the boundary.
- Tool execution must go through the Sandbox port; out-of-policy operations require approval. Worker processes must not spawn raw `child_process` (mock sandbox is fine in tests).
- Redact logs and events: no tokens, secrets, or full file contents.
- Outbound network (web_fetch/web_search) goes through an egress allowlist, off by default.

## 6. Testing Requirements

- **New/modified logic must come with tests**. Layers:
  - Pure functions (projections, reducers, renders) → unit tests, mandatory.
  - Web interactions → per-file jsdom environment with a fake ACP client; test focus/draft preservation and avoid rerendering unchanged history/messages while typing or streaming. Vitest inlines antd/antd-x for their ESM imports.
  - Port implementations → integration tests with in-memory fakes or testcontainers.
  - Loop → drive event sequences with fake `LLMPort` / fake `ToolRegistry`, assert the log event stream.
- Tests must be deterministic: no reliance on real network, real LLMs, or real clocks (inject a clock).
- Event-sourcing code must test the "crash recovery replay" path (torn-tail repair).
- Commands: `pnpm test`, `pnpm lint`, `pnpm typecheck` — all three must pass for work to be considered done.
- If the change is on docs, NO NEED to run tests.
- If the change is on backend only, no need to run frontend unit tests. Unless there are end-to-end tests.
- If the change is on frontend only, no need to run backend unit tests.

## 9. Agent Behavioral Guidelines

- Execution v2 preserves bounded authorized same-session user/final dialogue separately from preferences and model-directed `recall`; account recency and topic labels must not create objectives. Derive all current-request context from the committed message, preserve all text blocks, and keep assistant/compaction assembly separate. Persist one selection unless its delivered content changes; validate memory/recall fences before dispatch and effects. Keep `model-context/` artifacts private to runtime diagnostics; generic HTTP/blob tools must reject them. Rejected answer candidates survive replay/compaction separately from ordinary progress and can be expanded through `task candidate`. Plans and optional outcome assessments remain model-authored. Initial v2 plans may bind eligible earlier reads; changed checks/interpretations need fresh evidence, unchanged checks retain dependency-valid receipts, and adapter-owned effects invalidate current-state evidence conservatively. Legacy plans retain their recorded evidence semantics. See design §6.1.2 and `docs/intent-execution-design.md`.

- General action selection preserves user objectives across short continuations and never promotes earlier assistant proposals into requirements. Current run permission snapshots supersede historical assistant descriptions; execution checks remain authoritative. Task verify may select an exact eligible resultSeq or callId; both must agree, and original evidence fences remain authoritative. Pending command checks expose bounded replay-derived `commandRepairs` with the exact command and whether execution, fresh evidence or verification is needed; unmatched commands stay ineligible, and repair guidance never authorizes repeating mutations for bookkeeping. General repeated-failure/unchanged-read guidance is projected from current-prompt events without forcing completion. Optional `TASK_MAX_TOOL_CALLS` uses durable parent/child wave reservations before approvals/execution; rejected/crashed reservations remain spent, and exhaustion reserves a final-answer request subject to independent model budgets. Unset ceilings remain unlimited. Never expose physical KVM host diagnostics or escape paths to personal agents; measurements are of the assigned guest environment. See design §21.6 and intent-execution-design.md's 2026-10-25 update.

- Main and child loops share context/output sizing, strategy guidance, configured per-agent step ceilings and the durable task allowance. Delegation inherits cancellation/task deadlines without an extra hidden duration ceiling. Persist runtime-generated child activity/strategy summaries as parent progress through the existing ACP path; keep child evidence and reasoning private to its context, exclude progress from model history, and never promote child progress to a final report. These controls do not guarantee semantic task success. See design §6.3.
